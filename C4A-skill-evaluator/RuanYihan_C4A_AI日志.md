## 二、我如何指挥 AI（Prompt / 工作流设计）

我遵循"**先定目标 → 拆维度 → 分步指挥 → 证据验证**"，而不是一句话甩给 AI：

**第 0 轮 · 定框架（我给的方向）**
> "构建 C4A 技能提交自动评审器：输入一个群文件夹路径，扫描→完整性检查→四条件质量评审→生成报告。要可复用、可执行、可验证、IO 明确，且能从 wechat-doc-mapper 拿来改造。"

**第 1 轮 · 定标准（我给的硬约束）**
> "评审维度要按 c4_rubric.yaml 的信号定义；评分公式要可追溯；每个评级要能溯源到具体信号。输出 MD + Excel + HTML 三格式，含排名、改进建议、版本追踪。"

**第 2 轮以后 · 要证据（我反复强调）**
> "不能只给我代码，要在真实语料上跑出结果给我看，并写单元测试锁定行为。"

## 三、迭代过程（共 5 轮，每轮都改动了东西，含 3 次真实失败）

### 轮次 1 —— 架构成型
- **AI 做了什么**：搭出技能包骨架，写 config / scanner / completeness / quality / report / evaluator / CLI。
- **我做了什么**：审查模块划分是否对应 C4A 四级任务；要求"单一事实来源"（规则全进 c4_rubric.yaml）。
- **问题**：还没有运行证据。

### 轮次 2 —— 首次运行暴露"信号层级"Bug ❌（失败经验）
- **现象**：完整性检查对所有作者都报 0/5，明明文件名都符合规范。
- **排查**：定位到 `c4_rubric.yaml` 里检测信号嵌套在 `detection:` 键下，
  而我初版代码从 `spec.get("filename_patterns")` 顶层读取，读不到 → 全部落空。
- **修复**：改为从 `spec["detection"]` 读取。
- **教训**：**不能想当然认为规则结构是平的**——先读透数据结构的真实层级，再写解析。

### 轮次 3 —— 质量评审拿不到文件内容 ❌（失败经验）
- **现象**：四条件分数普遍偏低，IO 明确等项异常地判 ❌。
- **排查**：发现我初版只在"作者识别回退"时才读文件内容，其余文件 `_content` 一直是空，
  质量评审自然无米下锅。
- **修复**：把"读取文本内容"提到扫描主流程，无论作者识别成功与否都读取，供质量评审复用。
- **教训**：**一次扫描只读一次，且读取不能绑定在某个分支上**——数据采集与下游分析要解耦。

### 轮次 4 —— 误判率回归（最有价值的一轮，做了 3 次定向修复）
跑出首版报告后，我逐条核验，揪出 3 个会拉高误判率的错误：

| 误判 | 原因 | 修复 |
|------|------|------|
| 硬编码路径漏检 | `C:\Users\...` 大写盘符 + 正则要求小写；且 `https://` 里的 `s:/` 被误判成盘符 | 盘符检测改为大小写不敏感，并用"前一个字符非字母"排除 URL 协议 |
| `无安装说明` 被当"有安装" | 朴素子串匹配不看否定词 | 新增否定感知匹配：命中词前 4 字符内出现"无/没有/不/未"则不算命中 |
| `export WEATHER_API_KEY=xxx` 被当硬编码密钥 | 凭据正则太宽，任何 `key=` 都命中 | 凭据检测要求"密钥名 + 等号 + 带引号字面量"才算硬编码，环境变量用法不算 |
- **验证**：每条修复都补了对应单元测试，共 16 项，全部通过。
- **教训**：**评审器的价值上限由误判率决定**。评分再细，一误判就失去公信力。

### 轮次 5 —— 产物完整性与打包
- **我做了什么**：生成评审报告三件套（MD/Excel/HTML），回读 Excel 与 HTML 验证可打开；
  打包 `.skill`；核对命名规范与文件清单。

## 五、AAR 复盘（After Action Review）

### 1. 目标达成度
✅ 交付可复用、可执行、可验证、IO 明确的 `.skill` 技能包 + 6 份交付文档 + 报告三件套。
✅ 用真实语料（含本人真实 C4 提交）跑出**分层合理**的评审结果（100 / 92.5 / 76.5 / 22.5）。
✅ 用 16 项单元测试锁定"有测试用例、误判率低"。

### 2. 做得好的
- **把"评审准确性"落到证据**：每个评级可溯源到具体信号；误判场景逐一修复并回归。
- **单一事实来源**：规则全在 YAML，老师改标准不用碰代码，可复用性有保障。
- **文档闭环**：方案设计 / 教学说明 / AI日志 / 拿来说明四件套齐全，命名规范。

### 3. 踩过的坑（已记录）
- 规则数据结构想当然 → 先读透真实层级。
- 内容读取绑定错误分支 → 采集与分析解耦。
- 朴素匹配不看否定词/URL/大小写 → 误判率回归必须做成测试。

### 4. 改进方案（进 v2）
1. 接入真实 LLM 深审层（`LLMReviewer` 接口已留好），做语义级复核。
2. 支持自定义权重配置界面，老师可在仪表板上拖权重。
3. HTML 仪表板增加各维度趋势曲线（跨版本对比）。
4. 扩展评审维度（如"创新性 / 教学性"），与 C4A 评审标准扩展同步。

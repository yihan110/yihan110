# C4A 方案设计：技能提交自动评审器（Automated Skill Submission Evaluator）

> 提交人：RuanYihan（阮依涵）｜ 挑战：C4A 技能提交自动评审 ｜ 版本：v1.2
> 目标：把 `wechat-doc-mapper` 的"分类盘点"能力升级为"自动阅卷"能力，交付一个
> 可复用、可执行、可验证、IO 明确的技能提交自动评审技能。

---

## 一、问题与目标

C4 挑战要求每位同学提交一个可复用、可执行、可验证、IO 明确的技能包（5 个必需文件），
文件发到 WeChat 群。老师逐份检查存在三个痛点：

1. **谁交了、谁没交、交得齐不齐？**——需人工核对 5 个必需文件。
2. **交得合不合格？**——需按 C4 四条件（可复用/可执行/可验证/IO 明确）逐份评审。
3. **能不能自动给出初步评审？**——而不是等老师一个个看。

`wechat-doc-mapper` 已能做"扫描→分类→缺口分析"，但它只是"收发室"——能分信，不能阅卷。
**C4A 目标：把收发室升级为自动阅卷系统**，实现四级流水线：

```
WeChat 群文件夹
       ↓
  ① 文件采集与作者识别   （Level 1）
       ↓
  ② 提交完整性检查       （Level 2）
       ↓
  ③ 技能质量评审（四条件）（Level 3）
       ↓
  ④ 评审报告生成          （Level 4）
```

---

## 二、总体架构

技能包结构（模块与四级任务一一对应，单一职责、可单测）：

```
RuanYihan_C4A_skill-evaluator.skill/
├── SKILL.md                    # 主技能文档（触发 + 四步流水线 + 边界情况）
├── references/
│   ├── c4_rubric.yaml          # 机器可读评审规则（单一事实来源）
│   └── wechat_doc_mapper_notes.md  # 拿来主义分析
├── src/
│   ├── config.py               # 常量/命名规范/信号加载
│   ├── scanner.py              # L1 扫描、作者识别链、版本追踪
│   ├── completeness.py         # L2 五必需文件完整性检查
│   ├── quality.py              # L3 四条件质量评审（规则 + 可选 LLM）
│   ├── report.py               # L4 报告生成（Markdown/Excel/HTML）+ 排名 + 建议
│   └── evaluator.py            # 编排器（串起 1→4 级）
├── scripts/run_c4_evaluator.py # 命令行入口
└── tests/
    ├── test_c4_evaluator.py    # 16 项单元测试（误判率回归）
    └── fixtures/群文件/         # 拟真 C4 提交语料（同时作为测试用例）
```

**关键设计原则——单一事实来源**：全部评审信号（文件名模式、内容信号、正/负向信号、
评分公式）集中在 `references/c4_rubric.yaml`。代码只是执行器；老师要调评审标准，
改 YAML 即可，不用碰代码。这直接保障了"可复用性"。

## 三、四条件评审维度定义（核心创新）

把 C4 四条件翻译成**可检测的信号**，每条条件设 4 个 check items，命中 ≥2 记 ✅、
1 记 ⚠️、0 记 ❌：

| 条件 | check items（可检测信号） |
|------|--------------------------|
| **可复用** | ①有安装/依赖说明 ②列出环境/平台要求 ③**无硬编码路径/密钥** ④参数化/通用性说明 |
| **可执行** | ①含代码/函数/类定义 ②.skill 包或 YAML frontmatter ③可执行 workflow/步骤 ④含可运行入口/命令 |
| **可验证** | ①测试/测试用例 ②示例/演示 ③预期结果/判据 ④附 demo 视频/截图 |
| **IO 明确** | ①"输入X，输出Y"一句话 ②明确输入 ③明确输出 ④注明类型/格式 |

**评分公式**（对齐 c4_rubric.yaml）：
- 完整性分 = 已提交必需文件数 / 5
- 质量分 = 四条件（✅=1.0 / ⚠️=0.5 / ❌=0.0）均值
- 综合分 = 完整性 × 0.4 + 质量 × 0.6，映射到 0–100

**为降低误判率所做的针对性设计（含失败迭代）：**

| 易误判场景 | 处理 | 结果 |
|-----------|------|------|
| `C:\Users\...` 大写盘符 | 大小写不敏感盘符正则 + 排除 URL 协议（`https:/` 中的 `s:`） | 赵磊的硬编码路径被正确检出并降级 |
| `无安装说明`（否定句） | 否定感知匹配：命中词前 4 字符内出现"无/没有/不/未"等则不计命中 | "无安装说明"不再被误判为"有安装" |
| `export API_KEY=xxx`（环境变量用法） | 凭据检测要求"密钥 = 带引号字面量"才判硬编码 | 环境变量好实践不被误判为泄露密钥 |
| 内容层误报（如 AI 日志含"输出"被当 skill 说明） | 完整性两遍检测：文件名权威优先，内容回退仅用于文件名未命中的必需文件 | 报告干净、误报大幅下降 |

## 四、技术选型：规则 + 可选 LLM 混合（方案取舍）

Level 3 是核心创新。三种方案对比与决策：

| 方案 | 优点 | 缺点 | 本技能的选择 |
|------|------|------|-------------|
| **纯规则** | 确定性、快、零成本、可测试 | 覆盖率低、易误判（需精心设计信号） | ✅ **主引擎** |
| **纯 LLM** | 理解力强、灵活 | 不确定、慢、贵、无法写单测 | ❌ 仅作可选增强 |
| **规则 + LLM 混合** | 规则快筛 + LLM 深审，兼顾确定性与理解力 | 架构复杂 | ✅ **最终采用** |

**为什么选混合式**：C4A 的评审结果需要**可复现、可解释、可测试**（评审器质量维度要求
"评分标准清晰、有测试用例、误判率低"）。规则引擎的每个评级都能追溯到具体信号，老师可核验；
纯 LLM 虽理解力强但结果不确定。因此以规则为确定性主引擎，同时提供可插拔的
`LLMReviewer` 接口（`quality.py`），需要语义深审时再启用 LLM 做补充建议。默认关闭，
保证**离线、零依赖外部 API** 即可运行。

**为什么用两遍完整性检测**：第一遍文件名命中为权威信号（如 `_C4_skill说明.md`），
第二遍内容回退仅当某必需文件"文件名未命中"时启用，且内容命中标记为"⚠️ 需人工复核"，
避免把 AI 日志里的"输出"误判成 skill 说明文档。

## 五、四级任务覆盖

| 级别 | 能力 | 实现位置 | 状态 |
|------|------|----------|------|
| **Level 1** 文件采集器 | 扫描 `_C4_/_C4A_` 标记、作者识别链（文件名→子文件夹→内容→Unknown）、混合格式、版本追踪 | `scanner.py` | ✅ |
| **Level 2** 完整性检查器 | 5 必需文件两遍检测、齐全/部分/严重分级、缺失明细 | `completeness.py` | ✅ |
| **Level 3** 质量评审器 | 四条件规则评审 + 可插拔 LLM 深审、依据 + 改进建议 | `quality.py` | ✅ |
| **Level 4** 完整评审系统 | 班级总览、可配置权重排名、个性化建议、版本轨迹、MD+Excel+HTML 三格式 | `report.py` | ✅ |

## 六、真实验证与可靠性

- 用 6 位作者的拟真语料（含本人真实 C4 提交 `阮依涵_C4_*`）跑通全流程，产出
  `RuanYihan_C4A_评审报告.md` / `.xlsx` / `.html`。
- **16 项单元测试全部通过**，覆盖：作者识别、子文件夹回退、版本追踪、非 C4 过滤、
  完整性分级、否定词不误判、URL 不误判为盘符、环境变量不误判为凭据、硬编码路径正确降级、
  排名顺序、空文件夹等。
- 评审区分度合理：高质量完整提交 100 分 → 硬编码路径者 92.5 → 部分缺失 76.5 → 严重缺失 22.5。

## 七、边界情况

| 情况 | 处理 |
|------|------|
| 空文件夹/无 C4 文件 | 报告"未找到 C4 相关文件"，列出扫描路径与规则 |
| 文件名不规范 | 子文件夹名/内容回退，标记"需人工确认" |
| 超大文件（>50MB） | 跳过内容分析，仅文件名/类型匹配 |
| 二进制（.mp4/.png） | 仅文件名匹配（demo 判定依赖扩展名） |
| 非 C4 文件混入 | 过滤后单列"非 C4 文件"清单 |
| 同一作者多版本 `_v2/_v3` | 版本追踪，展示迭代轨迹，排名用最新版 |
| 编码问题（中文文件名） | UTF-8 优先，GBK 回退 |

---

## 八、可复用性与后续迭代

- **换老师/换班级直接用**：输入 = 一个文件夹路径；评审规则改 YAML 即可。
- **接 LLM 深审**：继承 `LLMReviewer`，把规则结果 + 提交内容交给大模型补语义建议。
- **v2 方向**：接入真实 LLM 深审层、支持自定义权重权重配置界面、HTML 仪表板增加趋势曲线。

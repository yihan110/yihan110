## 一、wechat-doc-mapper 是什么

`wechat-doc-mapper` 是一个"群文件收发室"技能：
输入 WeChat 群文件夹 → 扫描文件 → 按挑战/作者分类 → 缺口分析（谁缺了哪些文档）。
它的核心价值是**扫描 + 分类 + 缺口盘点**，但止步于"分信"，不能"阅卷"。
C4A 的本质就是把收发室升级为**自动阅卷系统**。

## 二、我拿了什么（继承，保持能力基线）

| 从 wechat-doc-mapper 拿来的能力 | 在本技能中的落点 | 取舍理由 |
|--------------------------------|-----------------|---------|
| 递归扫描文件夹、按 `_C4_` 标记识别 | `scanner.is_valid_c4_filename` / `scan_folder` | 扫描是最成熟部分，直接拿来避免重复造轮子 |
| 按作者分组返回 `Dict[author, List[file]]` | `ScanResult.authors`（数据结构沿袭） | 保证与既有 C4 流程数据口径一致 |
| 文件名 → 内容/元数据回退的作者识别链 | `scanner._author_from_subfolder` / `_author_from_content_heuristic` | 处理群提交常见的不规范命名 |
| 缺口分析（缺了哪几个必需文档） | `completeness.py`（升级为五必需文件矩阵） | 完整性检查的前身 |
| 混合格式支持（.md/.docx/.pdf/.mp4/.png） | `scanner.BINARY_EXTS` + 内容安全读取 | 群文件夹就是大杂烩 |

## 三、我改了什么（改造，补足 C4A 的核心）

| 改造点 | 原 wechat-doc-mapper | C4A 版本 | 为什么改 |
|--------|---------------------|----------|---------|
| **识别标记** | 仅 `_C4_` | 兼容 `_C4_` / `_C4A_` / `-c4-` | C4A 提交本身用 `_C4A_`，必须识别 |
| **完整性检查** | 泛化"文档缺口" | 严格对照 5 必需文件 + 两遍检测 + 齐全/部分/严重分级 | 对齐 C4 规范，降低误判 |
| **作者识别链** | 文件名→子文件夹 | 增加内容回退（`提交人：`），并标记 `Unknown` 待人工 | 更鲁棒处理不规范命名 |
| **新增质量评审** | 无（只盘点不评分） | `quality.py` 四条件（可复用/可执行/可验证/IO明确）规则+可选LLM | **这是 C4A 的本质飞跃：收发室→阅卷系统** |
| **新增报告** | 纯文本盘点 | Markdown + Excel + HTML 三件套，含排名/建议/版本轨迹 | Level 4 班级总览与可视化 |
| **新增测试** | 无 | 16 项单元测试 + 拟真语料 | 评审器质量维度要求"有测试用例、误判率低" |
| **新增版本追踪** | 无 | 识别 `_v1/_v2`，展示迭代轨迹 | Level 4 进步轨迹要求 |
| **新增可插拔 LLM** | 无 | `LLMReviewer` 接口（规则快筛 + LLM 深审） | 兼顾确定性与理解力 |

## 四、为什么这么改（关键取舍）

1. **为什么把质量评审做进规则层而非只靠 LLM**：C4A 评审结果需要**可复现、可解释、可测试**。
   纯规则给出可溯源的命中依据（每个评级能追到某条信号），老师能核验；纯 LLM 结果不确定、
   无法写单测。因此采用「规则主引擎 + 可选 LLM 深审」混合方案。
2. **为什么保持单一事实来源**：全部信号集中在 `references/c4_rubric.yaml`，代码只是执行器。
   老师要调标准改 YAML 即可——这是"可复用性"的保障。
3. **为什么保留内容回退且标记复核**：文件名不规范是群提交常态，内容回退提高召回率；
   但内容命中可能误判，故标记"⚠️ 需人工复核"，宁标记不乱判，保证误判率低。

## 五、超越：C4A 相对 wechat-doc-mapper 的新能力清单
1. 五必需文件自动完整性判定（分级状态 + 缺失明细）
2. 四条件质量自动评分（可追溯依据 + 针对性改进建议）
3. 班级排名（可配置权重，`weights` 参数）
4. 版本轨迹追踪（`_v1/_v2`）
5. 三格式报告（MD / Excel / HTML 仪表板）
6. 内置 16 项单元测试与拟真语料（可验证、可回归）
7. 可插拔 LLM 深度评审接口（`LLMReviewer`）
8. 误判率专项优化：否定感知匹配、URL/盘符区分、环境变量 vs 硬编码凭据区分

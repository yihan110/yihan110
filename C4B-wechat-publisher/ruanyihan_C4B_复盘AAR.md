## 2. 做得好的三件事

### 2.1 把「可验证」做成了证据链，而不是口头声明

我没有停在「我做了个技能」。我为每一类能力都写了断言，最终形成 22 项自检：

```
[PASS] h1 已降级（无 <h1>）
[PASS] callout NOTE 渲染
[PASS] 中英文间距（盘古之白）
[PASS] 数学公式转 PNG base64
[PASS] 输出不含 <html>/<body> 外壳
[PASS] 全角标点前不插细空格
...
结果：22/22 通过
[validate] ✓ 通过公众号 HTML 规则校验
```

**「我说它能用」和「它跑给我看能用」是两回事。** 前者是声明，后者是证据。

### 2.2 把「缺陷」变成了「测试用例」

从 starter kit 里挖出的 7 个缺陷（`<hr>` 静默丢弃、`get_text()` 拍平嵌套、
`ALLOWED_CSS` 死代码……）没有只写进文档，而是**每一条都变成一个断言**。
这样缺陷不但被修掉，还被永久锁死了 —— 以后改代码只要碰坏了，自检立刻报错。

### 2.3 主题做成数据，不做成分支

5 套主题全是字典数据，代码里没有一处 `if theme == "xxx"`。
加一套新主题只需要往字典里加一项。这是「可复用性」的落地方式：
**把变化点抽成数据，别人扩展时不用读逻辑。**

## 3. 具体问题（逐条分析，含失败经验）

| 问题 | 事实 | 根因 | 修复 / 影响 |
|------|------|------|------------|
| **P1 Windows GBK 崩溃** | starter kit 跑官方示例直接抛 `UnicodeEncodeError` | `print()` 输出 emoji，中文 Windows 控制台是 GBK | 启动强制 UTF-8。**教训：本地化盲区比逻辑 bug 更致命** |
| **P2 Callout 拆不开** | 首版自检 `[FAIL] callout NOTE/WARNING` | Markdown 把标记行与正文行合并进同一个 `<p>`，后处理无法拆分 | 改为**解析前**逐行预处理。**教训：处理要前置到数据未变形时** |
| **P3 输出套了「页面里的页面」** | 高亮框里出现嵌套 `<html><body>` | `BeautifulSoup(fragment)` 会自动补全文档结构 | 改为搬运 DOM 节点。**教训：字符串与节点不能混用** |
| **P4 标点被插错空格** | 输出出现 `坑 1 ： emoji`、`1.75 、给引用` | 我的 CJK 字符集把全角标点也算进去了 | 字符集收窄到只含汉字。**教训：范围定义过宽比功能缺失更伤人** |
| **P5 正文片段夹带外壳** | `_body.html` 开头有 `<html><body>` | 用了 `str(soup)`，lxml 会自动补全外壳 | 只取 `<body>` 的子节点 |
| **P6 自检用例本身是错的** | `[FAIL] 中英文间距`，但技能其实是对的 | 测试句子里中英文之间本来就有空格，从未触发条件 | 换成真正的无空格混排样例。**教训：测试也要被验证** |
| **P7 无法产出真实发布链接** | 见第 5 节 | 发布需登录公众号后台，非脚本可完成 | 已提供完整发布 SOP + 截图位置，待人工回填 |

## 4. 三条值得长期记住的失败经验

### 4.1 「跑起来」和「以为跑起来了」之间，隔着一整个 Windows 编码体系

starter kit 的作者显然在 Mac/Linux 上开发。一行 `print("📖 ...")` 在他那里毫无问题，
到了中文 Windows 上直接终止程序。

**这提醒我：任何工具的「跨平台可用」都不是默认成立的。** 交付前必须在目标环境真跑一遍。
我在 C2G 挑战里也踩过类似的坑（`python3` 在 Windows 上是 0 字节占位符导致 9009 错误）——
**同一个模式反复出现：作者环境 ≠ 用户环境。**

### 4.2 后处理阶段的挣扎，往往源于上游把信息揉成了一团

Callout 那一轮我卡了很久，一直想用更复杂的正则从 `<p>` 里硬拆标题和正文。
真正的解法不是「更聪明的正则」，而是**把处理提前到 Markdown 解析之前**。

**当你在一个环节反复挣扎时，应该退一步问：是不是上游丢失了边界信息？**

### 4.3 写宽了的规则，比没写的规则更糟

「中英文加空格」听起来是个贴心功能，但我的第一版把全角标点也纳入了边界判断，
结果满篇 `1 ：`、`1.75 、` —— **比不加空格还难看**。

**规则的价值取决于边界的精确度，而不是覆盖面的广度。**

## 8. 一句话总结

> 这次最大的收获不是「做出了一个排版技能」，而是理解了一件事：
> **AI 能十分钟写出 500 行代码，但它不知道 emoji 会在你的终端上崩，
> 不知道清洗规则会静默吞掉 `<hr>`，也不知道你的测试样例本身是错的。**
> 这些只有真正跑起来、真正在意结果的人才会发现。

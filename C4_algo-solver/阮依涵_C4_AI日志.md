## 二、我如何指挥 AI（Prompt / 工作流设计）

我遵循"**先定目标 → 拆维度 → 分步指挥 → 证据验证**"的方式，而不是一句话甩给它：

**第 0 轮 · 定框架（我给的方向）**
> "做一个可复用、可执行、可验证、IO 明确的算法题解技能，要契合我的软件工程 + 算法竞赛背景，让别人能直接用。"

我对 AI 明确提了 4 条硬约束（对照 C4 技能四条件）：
1. 必须有一个**真实可运行的脚本**（体现"可执行"，而不是纯描述）。
2. 必须有**明确输入输出**（一句话能说清"输入题目 → 输出代码+评测"）。
3. 必须**可验证**（给测试输入 → 能判断对错）。
4. 必须**不依赖我个人的环境**（别人拿去也能跑）。

**第 1 轮 · 要结构（我给的标准）**
> "按 Claude Skill 标准结构：SKILL.md（YAML frontmatter + 工作流 + 边界情况 + 示例）+ scripts/ + references/ + assets/。"

**第 2 轮以后 · 要证据（我反复强调）**
> "不只要给我代码，要实际跑给我看：正确题解全过、错误题解被抓出来。"

## 三、迭代过程（共 4 轮，每轮都改了东西）

### 轮次 1 —— 初版成型
- **AI 做了什么**：搭建 `algo-solver/` 目录，写出 SKILL.md（5 步工作流）、`judge.py`（编译/运行/比对）、复杂度速查表、算法模板、示例题目。
- **我做了什么**：审查了描述字段是否够"主动"（加了中英双语触发短语）、工作流是否覆盖边界情况。
- **问题**：尚无运行证据。

### 轮次 2 —— 首次运行暴露 Windows 坑 ❌（失败经验）
- **现象**：跑 `judge.py`，全部测试报 `runtime error 9009`。
- **排查**：9009 = Windows"找不到可执行文件"。定位到 `shutil.which("python3")` 解析到系统自带的 `WindowsApps\python3.EXE` **占位符**（0 字节 stub），执行即失败；而真正的 Python 是 `python`。
- **修复**：改写为优先使用 `sys.executable`（正在运行的真实解释器），并增加 `_skip_windowsapps()` 过滤掉 WindowsApps 占位符。
- **教训**：跨平台脚本必须警惕 Windows 应用商店别名，不能想当然认为 `which("python3")` 可用。

### 轮次 3 —— 测试数据自身有 bug ❌（失败经验）
- **现象**：Test 3 一直 FAIL（output mismatch）。
- **排查**：发现是我造的测试用例本身违反题设（"恰有一个答案"），该输入下没有两数和等于 target，期望输出是错的。
- **修复**：重写 Test 3，改为覆盖**大整数边界**（`±10^9`）且答案合法。
- **教训**：测试用例也是要验证的对象，不能"随手写个期望"就当标准。

### 轮次 4 —— 负向测试抓不住 bug ❌（最有价值的一轮）
- **现象**：故意写错的 `buggy.py`（只检查相邻两数）竟然 3/3 全过。
- **排查**：因为我的 3 个测试里答案恰好都是**相邻元素**，这个 bug 被掩盖了。
- **修复**：新增 Test 4——`1 5 2 3 4 / 9`，答案是下标 `1 4`（**不相邻**）。再跑：
  - `buggy.py` → Test 4 **FAIL（output mismatch）** ✅ 抓到
  - `solution.py` → **4/4 PASS** ✅
- **教训**：**验证的充分性取决于测试用例的质量**。评测器再强，用例覆盖不到，也抓不出 bug。这是"可验证"的真谛——不是工具存在就够，是证据链条完整才算。

### 收尾
- **我做了什么**：用 PIL 把真实运行输出渲染成 demo 截图；打包 `.skill` 并解压验证结构；核对文件清单与命名规范。

## 五、AAR 复盘（After Action Review）

### 1. 目标达成度
✅ 交付了可复用、可执行、可验证、IO 明确的 `.skill` 技能包 + 4 份文档 + demo 截图。
✅ 用**真实运行输出**（4/4 PASS + 负向 FAIL）而非口头声明来证明"可验证"。

### 2. 做得好的
- **把"可验证"做成证据**：不止说"能验证"，而是实际跑出正确题解全过、错误题解被抓。
- **测试用例覆盖意识**：专门加"非相邻答案"用例去暴露常见 bug。
- **文档闭环**：skill说明 / 教学说明 / AI日志 / demo 四件套齐全，命名符合规范。

### 3. 踩过的坑（已记录）
- Windows `python3` 占位符导致 9009 → 用 `sys.executable` 根治。
- 测试数据自身错误 → 测试也要验证。
- 用例覆盖不足掩盖 bug → 用针对性用例暴露。

### 4. 改进方案（进 v2）
1. **支持 Java / Go**：在 `judge.py` 增加编译器分支（比对逻辑已通用）。
2. **HTML 评测报告**：把 `verdict_report.txt` 升级为带高亮的 HTML，便于贴群展示。
3. **更多算法模板**：补充 DP、图论、字符串等模板到 `algo-templates.md`。
4. **"一键自检"**：让技能用 sample 题目 + `--tl 1` 跑一遍内置冒烟测试，确保交付前自证可用。
5. **收集同学反馈**：记录大家遇到的报错/不便，按优先级迭代。

## 六、对"被使用"的思考（C4 核心）

这个技能设计上**优先照顾"人人都能用"**：
- 不要求 g++，Python 即可跑通 → 覆盖不会 C++ 的同学。
- 不需要任何 OJ 账号 → 本地就能验证。
- 交付物自带证据 → 用了的人能立刻感受到"省了盲交的挫败"。

**欢迎使用，反馈越多，v2 越好。**

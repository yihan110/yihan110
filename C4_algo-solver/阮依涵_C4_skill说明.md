## 一、一句话说明（Clear I/O）

**输入**一道算法题（题目文字 / 截图 / 粘贴的题面），**输出**一份可直接提交的 ACM 模式代码 + 算法思路 + 复杂度分析 + 一份**真实跑出来的评测报告**（PASS/FAIL）。

> 别人只要把题发给我这个技能，就能拿到"能跑、能过样例、还自动测过边界"的题解，而不是一段没人验证过的代码。

---

## 二、解决什么问题（Why）

每个 CS 学生都反复做同一件事：读题 → 想算法 → 写 ACM 模式代码 → 交到 OJ（PAT / 牛客 / LeetCode / 力扣）→ 发现 WA / TLE / RE。最耗时间的其实不是"想"，而是最后两步：

- **写出来的代码有没有 bug？**（数组越界、int 溢出、输出多一个空格、边界没处理）
- **交上去会不会挂？**（只有自己"感觉对了"，没有证据）

传统做法是"写完直接交，WA 了再改"，一次提交失败在真实 OJ 上会扣分、限次，甚至影响比赛心态。**algo-solver 把"提交前验证"自动化**：先想清楚算法（按约束选复杂度），再写代码，再用随附的 `judge.py` 对官方样例 + 自造边界用例**自动编译运行比对**，全过才交付。

**类比**：它像一个私人算法教练——不只给你答案，还会先"做一遍评测"证明答案是对的，再交给你去提交。

## 四、技能四条件（Reusable / Executable / Verifiable / Clear I/O）

| 条件 | 本技能如何满足 | 检验方法 |
|------|----------------|----------|
| **可复用** | 不依赖我的环境；只要装好 Python 3（可选 g++）就能跑；题面可以是任意题目 | 陌生人下载 `.skill`，按教学说明操作一遍能否成功 |
| **可执行** | 不是理论：`scripts/judge.py` 是真实可运行的评测器，会**编译、运行、比对输出** | 运行 `python3 judge.py solution.py --tests ./tests` 有真实输出 |
| **可验证** | 有明确输入输出：给定测试输入 → 输出必须等于期望输出，全过才 PASS | 给定 `tests/*.in`，能稳定得到对应 `.out` 判定 |
| **IO 明确** | 一句话：输入题目 → 输出 `problem.md` + `solution.cpp/py` + `verdict_report.txt` | 一句话能复述 |

**实证**（本人已在本机真实运行）：
- 正确题解 `solution.py` 对 4 组测试（样例、负数、大整数、非相邻答案）**4/4 PASS**。
- 故意写错的 `buggy.py`（只检查相邻两数）在同一测试集**第 4 组被自动抓出 FAIL**，证明验证器不是摆设。

## 五、技能架构

```
algo-solver/                         # .skill 包解压后
├── SKILL.md                        （主指令，含触发描述 + 5 步工作流 + 边界情况）
├── scripts/
│   └── judge.py                    （评测器：编译/运行/比对输出，多语言可扩展）
├── references/
│   ├── complexity-cheatsheet.md    （约束 → 可行复杂度 → 算法选择对照表）
│   └── algo-templates.md           （快速IO/二分/前缀和/DSU/快速幂等 10 套模板）
└── assets/
    └── sample-problem.md           （示例题目"两数之和"，用于上手测试）
```

**三层加载机制**：`description`（触发入口，中英双语短语）→ `SKILL.md` 正文（< 500 行）→ references/scripts（按需加载）。

## 六、使用步骤（How）

1. **给题**：把题目文字 / 截图发给技能，或说"解这道题"。
2. **重述**：技能先写 `problem.md`，抓 4 个要素：任务、输入格式、输出格式、**约束**（决定算法）。
3. **选算法**：按约束对照 `complexity-cheatsheet.md` 选复杂度与数据结构，说明为什么朴素做法会 TLE。
4. **写码**：生成 ACM 模式 `solution.cpp` 或 `solution.py`（快速 IO、`long long`、精确输出格式）。
5. **自动验证**：
   ```bash
   python3 scripts/judge.py solution.cpp --tests ./tests   # C++
   python3 scripts/judge.py solution.py  --tests ./tests   # Python
   ```
   `tests/` 放 `1.in`/`1.out` 配对，先放官方样例，再补 2–3 个边界用例。
6. **交付**：代码 + `verdict_report.txt` + 算法讲解。全部 PASS 才说"可提交"。

## 七、真实案例（已实测）

**题目**：两数之和（`n ≤ 10^5`，找两数和为 target 的下标）。

- **输入**：`4 / 2 7 11 15 / 9`
- **输出**：`0 1`

**过程**：约束 `n ≤ 10^5` → 暴力 `O(n^2)` 会 TLE → 选哈希表 `O(n)`。写 `solution.py`，构造 4 组测试：官方样例、负数、大整数边界（`±10^9`，验证 `long long` 溢出）、**非相邻答案**（专治"只看相邻"的常见 bug）。

**评测结果**：
```
Test 1: PASS   Test 2: PASS   Test 3: PASS   Test 4: PASS
Summary: 4/4 PASS
```
同一测试集下，错误的 `buggy.py` 第 4 组 `FAIL (output mismatch)`，验证器准确抓错。

## 七·补、真实真题验证（更新于 2026-10-10）

技能不只对示例题有效——**对网上找的真实 OJ 真题同样当场跑通**，这是对"可复用 + 可验证"最强的实证。

**真题 A：PAT 乙级 1009「说反话」（浙江大学 PTA 真题）**
- 输入：`Hello World Here I Come` → 输出：`Come I Here World Hello`
- 评测：**3/3 PASS**（官方样例 / 单单词 / 多单词边界）
- 复现：仓库 `demo_pat1009/`

**真题 B：区间和查询（`n,m ≤ 10^5`）**
- 用前缀和 `O(n+m)` 取代暴力 `O(n·m)`（后者会 TLE）——体现"按约束选算法"
- 评测：**3/3 PASS**（样例 / `n=1` / 大整数边界）
- 复现：仓库 `demo_range_sum/`

> 每次都是"写代码 → `judge.py` 自动评测 → 全过才交付"，不是直接甩答案。

## 八、为什么值得被使用（对同学的收益）

- **省时间**：写完不用"盲交"，先在本地过一遍评测。
- **避免 WA**：输出格式、边界、溢出这些最常见的坑，评测器替你盯住。
- **学得会**：每个答案都带"为什么是这个算法 + 复杂度"，不是只给代码。
- **零门槛**：不要求同学有 g++，用 Python 题解即可跑通全部流程。
